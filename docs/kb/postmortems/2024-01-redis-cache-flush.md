## 根因分析

### 直接原因
开发人员在调试时，误将本地 Redis 客户端指向生产环境，执行 `FLUSHALL` 清空了全部缓存。

### 深层原因
1. **环境隔离不足**：开发人员的 SSH key 可以直接连到生产 Redis，没有跳板机限制
2. **Redis 未开启 ACL**：所有连接都有 FLUSHALL 权限
3. **无缓存预热机制**：缓存清空后所有请求直接穿透到数据库
4. **数据库连接池容量不足**：无法承受缓存失效后的突发流量

## 经验教训

1. **危险命令必须有权限控制**：FLUSHALL/FLUSHDB 在生产环境应限制为运维角色
2. **缓存失效要有兜底**：不能假设缓存永远在，要有降级和预热机制
3. **环境隔离是底线**：开发环境绝不能直连生产数据层
4. **止血优先于根因**：先限流止血，再查谁干的
